Read CLAUDE.md and PLAN.md, especially the Replay design section. Task B4: process replay. Budget: 35 minutes. This is the signature feature, but correctness beats polish: build recorder, then server, then facts, then player, and test the fidelity requirement early.

1. Recorder (client, `src/features/replay/recorder.ts`): hook into Tiptap `onTransaction`. For each `docChanged` transaction capture serialized steps, kind (paste when `tr.getMeta("uiEvent") === "paste"`, drop treated as other, undo/redo from the history meta, otherwise type, delete or format based on the steps), inserted and deleted character counts, and `client_t` (ms since the session started). Buffer in memory and flush every 2s, on blur, and on `pagehide` via `navigator.sendBeacon`. Each batch carries a contiguous client `seq`. Do not record anything for read-only viewers.
2. Server: `POST /api/docs/:id/events` (editor access required). Validate with zod, require contiguous seq (reject gaps and duplicates with 409), stamp `received_at`, clamp `client_t` so it never exceeds real elapsed time since the previous event, append only (there is NO update or delete route for events). Store a full-document checkpoint at seq 0 (initial content, from creation or import) and every 100 events (the client sends the doc JSON for those).
3. `GET /api/docs/:id/replay`: returns checkpoints and events in order. Access: owner, editors, and the assignment teacher (added in B5). Viewers and commenters who are not the teacher get 403.
4. Facts (`src/features/replay/facts.ts`, pure function, unit tested): active writing time (gaps over 2 minutes count as idle), sessions (a new session starts after a gap over 30 minutes), revision count, paste events (time and size), and percent of inserted characters by source: typed, pasted, imported. Facts only. No scores, no flags, no words like "suspicious" or "likely AI". Label the percentage "of characters inserted" so it is not misread as a share of the final text.
5. Player UI (`/docs/[id]/replay`, also reachable from a "Replay" button in the editor header):
   - Read-only Tiptap editor that rebuilds state with `Step.fromJSON(schema, json)` from the nearest checkpoint, so scrubbing is fast.
   - Controls: play and pause, scrub bar with markers where paste events happened, speeds 1x, 4x, 16x, "Skip idle gaps" toggle (on by default), current timestamp and event count.
   - Paste events highlight the inserted range briefly during replay only (a decoration, never stored in the document and never shown in the live editor).
   - A facts panel beside it. Keep the design calm and readable.
6. Tests (required): (a) fidelity: simulate a realistic editing session (typing, a paste, a delete, formatting, an undo), record the events, replay from the first checkpoint, and assert the resulting document equals the saved final document exactly; (b) facts computed correctly on a fixed fixture including idle gaps and sessions; (c) server rejects seq gaps and duplicates; (d) a viewer without replay access gets 403; (e) there is no way to modify a past event.

If step replay breaks on some transaction types (tables, images), fall back to storing a full snapshot for that batch instead of steps, and say so in AI_LOG.md.
